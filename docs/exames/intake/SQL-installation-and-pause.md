# Private intake SQL package

Install [migration 23](../../../supabase/migrations/20261027000023_exam_intake_receipts_incidents.sql), then [migration 24](../../../supabase/migrations/20261027000024_exam_hopelab_notice_snapshots.sql), only after the separate read-only [preflight](intake-preflight.sql) matches the captured production definitions. The migrations start no collectors and keep WhatsApp alerts disabled. They contain no destination phone, clinical data or credentials.

The core reuses the existing collection cursor/sweep/message/origin/event tables. A source receipt persists across runs; each run still needs its own observed outcome. Every valid event renews the fenced lease using its original TTL. Heartbeats do not count as collection progress. Incomplete runs do not advance the checkpoint. Audit runs never advance an operational checkpoint or modify clinical documents through ledger RPCs.

The health check opens a persistent incident for a discovered/pending/failed receipt after ten minutes, and for an eligible canonical saved original without a proven group delivery after fifteen minutes. Group checks honor the configured operational notification cutoff and exclude explicit synthetic fixtures. Proven preservation, exclusion, delivery or an authorized group exception resolves the corresponding incident; unresolved or uncertain sends remain visible. A recovered incident cancels only alerts whose external submission has not started.

`reserve_source` in the Edge Function must call `reserve_exam_intake_source`; `stage_file` must call `stage_exam_intake_file`. Normal originals delegate to the previous core unchanged. A Hopelab v2 notice gets its own source by notice ID and link key. The URL digest relates snapshots; it does not replace the source identity or prove unchanged content. The reservation ACK is computed by the server after checking the hold installation.

The group reservation function changes only by adding the hold predicate before task claim. PostgreSQL CREATE OR REPLACE preserves its owner/ACL; migration 24 verifies both. The old reserve-source and stage-file definitions are not overwritten. A new changed snapshot is preserved independently and requires an authorized review before group reservation. Exact duplicate bytes reuse the existing canonical document and preserve any preexisting hold. No delivered/submitted/uncertain task is reset. A historical link with no preserved earlier original remains held as unproven history.

After installing, run `intake-postflight.sql`. It returns metadata and counts, not documents or patient identities. Expected initial state: eight new RLS tables, no direct anon/member table reads, worker-only collection/dispatch RPCs, member-only panel/acknowledgement RPCs, member veterinarian/admin review enforced internally, group hold predicate present, original source/stage/membership definitions unchanged, and automatic alert delivery disabled.

To pause, first stop the v2 collector/alert schedules and prospective cutover in the application/workflows, then run `intake-pause-without-data-loss.sql`. Keep all receipts, incidents, snapshots, source/file failure triggers and the group hold predicate. Preserve the panel and existing provider receipts. This pause performs no deletion, no retry and no external send. Do not remove the hold guard while a changed/unproven snapshot remains held; doing so could release an unreviewed document. Restoring old code later requires a reviewed migration using the privately captured original definitions and a separate check of all held documents and in-flight alerts.

The SQL cannot report a complete database outage by itself. An independent supervisor must call the health/alert routes and report failure to reach them. Provider pagination completeness remains an adapter obligation; SQL verifies the persisted inventory and outcomes rather than trusting saved-file counts.

From the repository root, validate the incremental installation and its boundaries with `node --test scripts/exames/intake/exam-intake-ledger.test.mjs`. The test uses the existing synthetic collection fixture and the checked-in migration SQL, including an actual database close/reopen; it does not contact production or providers. The production body hashes in preflight are intentionally tied to the captured baseline and must be reviewed again if those core definitions change.
